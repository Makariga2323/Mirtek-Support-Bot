# Mirtek Support Bot

Интеллектуальный сервис автоматической обработки клиентских обращений ООО «Миртек».
Партнёрский проект Городского Классического Лицея и ООО «Миртек».

## Что делает сервис

Принимает вопрос клиента текстом через API, определяет, о чём он, находит данные и формирует ответ.
Если надёжный ответ невозможен, обращение передаётся оператору.

## Структура репозитория

- `backend/`   сервис (FastAPI): `main.py` (API), `service/` (ядро, хранилище, сообщения), `logic.py`
- `prototype/` демо-интерфейс: `index.html` (вход), `chat.html` (чат), `operator.html` (очередь оператора)
- `data/`      тестовые данные `MOCK_DATA.json` (вымышленные)
- `tests/`     автоматические тесты, набор для замера KPI (`eval_set.json`, `kpi_eval.py`)
- `docs/`      документация API (`api-contract.md`) и архитектуры

## Установка и запуск

Нужен Python 3.13 (подойдёт 3.11+).

```bash
git clone https://github.com/Makariga2323/mirtek-support-bot.git
cd mirtek-support-bot
git checkout dev

python -m venv .venv
# Windows: .venv\Scripts\activate      Linux/macOS: source .venv/bin/activate
pip install -r backend/requirements.txt

cp backend/.env.example backend/.env     # Windows: copy backend\.env.example backend\.env
```

Откройте `backend/.env` и задайте свои токены:
`API_TOKENS` (вход клиента) и `OPERATOR_TOKENS` (вход оператора). Они должны отличаться.

Запуск сервера (из папки `backend`):

```bash
cd backend
uvicorn main:app --port 8000
```

Демо-интерфейс: откройте папку `prototype` через Live Server (адрес `http://127.0.0.1:5500`, он разрешён в `CORS_ORIGINS`)
или командой `python -m http.server 5500` в папке `prototype`.

- Чат: `http://127.0.0.1:5500/index.html` (вход по токену из `API_TOKENS`)
- Очередь оператора: `http://127.0.0.1:5500/operator.html` (токен из `OPERATOR_TOKENS`)

Адрес сервера для интерфейса задаётся в `prototype/config.js`.

## Режимы ядра

| `CORE_MODE` | Что это | Нужна модель |
|---|---|---|
| `rules` | **Рекомендуется.** Программная классификация и ответы по данным `MOCK_DATA.json`: наличие и цена, график работы, акции, доставка и самовывоз, возврат, FAQ | нет |
| `llm` | Данные + языковая модель: код собирает контекст, модель формулирует ответ, проверка отклоняет числа, которых нет в данных | да |
| `stub` | Демо-заглушки по ключевым словам (`backend/logic.py`) | нет |

Режим `rules` (`backend/service/rules_core.py`): тип вопроса определяется по смыслу (шаблоны, а не список готовых фраз),
товары и магазины ищутся по названию, синонимам и артикулу. Все значения берутся из данных: остатки считаются с учётом
резерва, график учитывает праздники и особые дни, акции показываются только действующие на дату. Составной вопрос
обрабатывается целиком или уходит оператору. Нет товара или данных, неизвестная тема, просьба позвать оператора,
иностранный язык, неизвестный город доставки: обращение уходит оператору, ответ не придумывается.

Ограничения режима `rules`: понимает типовые формулировки, но слабее модели справляется с нестандартными;
часть составного вопроса про неизвестную тему может быть не замечена. Для живой модели есть режим `llm`
(`backend/service/real_core.py`): нужны `LLM_BASE_URL` (любой OpenAI-совместимый API), `LLM_MODEL`, `LLM_API_KEY`.

## Настройки (`backend/.env`)

| Переменная | Значение |
|---|---|
| `API_TOKENS` | токены клиентов через запятую |
| `OPERATOR_TOKENS` | токены операторов через запятую |
| `CORS_ORIGINS` | адреса демо-интерфейса |
| `CORE_MODE` | режим ядра: `stub` или `llm` |
| `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` | подключение к модели (режим `llm`) |
| `DATA_PATH` | путь к `MOCK_DATA.json` (по умолчанию `data/MOCK_DATA.json`) |
| `DB_PATH` | файл базы SQLite |
| `REQUEST_BUDGET_S` | бюджет времени на запрос, секунд (по ТЗ 5) |
| `SESSION_TTL_S`, `MESSAGE_RETENTION_S`, `STALE_PROCESSING_S` | сроки хранения и восстановления |

## Тесты и проверка KPI

```bash
pytest                          # из корня репозитория
python tests/kpi_eval.py        # при запущенном сервисе: API_TOKEN=<токен клиента>
```

Результаты замера KPI записывайте в `docs/kpi.md`.

## Ограничения мок-данных

- Данные в `data/MOCK_DATA.json` вымышленные: 30 товаров, 3 магазина, 7 акций и т. д.
- Ответы режима `stub` (`backend/logic.py`) это заглушки с пометкой `[демо]`.
- Интеграции с Telegram, маркетплейсами, 2ГИС и реальными системами «Миртека» не входят в проект.
- Заявки хранятся вместе с сессией и удаляются при её завершении (прототип).
